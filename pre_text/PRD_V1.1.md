## 1. 产品概述

### 1.1 产品背景

当前火灾调查和勘察多依赖于火灾后的现场静态三维重建（通过 4D看看等全景相机设备）。为了更直观地复盘火灾发生过程、辅助案件调查及消防培训，需要将静态的"灾后现场"转化为动态的"灾中演变"视频。

### 1.2 产品定位与目标

打造一个**单机版 Web 应用**（V1）。用户输入全景相机的场景编号（sceneCode），系统自动：

1. 调用 4DKankan 开放接口拉取该场景的三维模型（OBJ）、全景图、采集点位与点云数据；
2. **自动识别烧毁最严重的区域**作为起火点；
3. 基于房间拓扑与烧毁程度**程序化计算火势蔓延时序**；
4. 通过 Blender 后台（子进程）生成火焰/烟雾/焦痕动画并渲染；
5. 输出 1080P 火灾时序演变视频（MP4），支持在线预览与下载。

> **产品定位声明**：本产品输出的视频为"基于场景几何形态与烧毁痕迹的火灾蔓延规律演示"，用于复盘辅助与培训素材，不作为火灾责任认定等司法结论的依据。

### 1.3 三大核心决策（已拍板）

| 决策点 | 结论 |
|---|---|
| 模拟路线 | **程序化蔓延**（房间级拓扑 + 烧毁程度驱动的时序算法 + 粒子/体积火焰表现），不采用 Mantaflow 全物理模拟 |
| V1 部署形态 | **单机 Web 应用**（本机运行，localhost 访问，单任务串行） |
| 起火点选取 | **自动识别烧黑区域**（全景图烧黑像素分析 → 房间级烧毁评分 → 评分最高者为起火点），支持手动修正 |

## 3. 核心业务流程

```
┌──────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ 用户输入   │   │ 数据抓取      │   │ 起火点识别    │   │ 蔓延时序计算  │
│ sceneCode│──>│ 鉴权+接口调用  │──>│ 烧黑区域分析  │──>│ 房间图蔓延    │
└──────────┘   └──────────────┘   └──────────────┘   └──────────────┘
                                                              │
┌──────────┐   ┌──────────────┐   ┌──────────────────────────┐
│ 结果交付   │<──│ FFmpeg 转码  │<──│ Blender 子进程渲染        │
│ 预览+下载  │   │ 720P 生成    │   │ 火焰/烟雾/焦痕/运镜动画     │
└──────────┘   └──────────────┘   └──────────────────────────┘
```

1. **输入**：用户输入 sceneCode，可选设置视频时长、蔓延速度倍率、分辨率档位；
2. **鉴权**：使用接入信息中的 appkey（Authorization 头）或 `/user/v1/login` 获取的 token；
3. **数据抓取**：并行/顺序调用接口，下载 OBJ、全景图、点位信息、点云，**即时转存**到本地数据目录（下载链接为临时签名 URL，不可留存）；
4. **起火点自动识别**：对每个采集点位的全景图做烧黑像素分析，结合点位所属房间（point info 的 room 字段），计算房间级烧毁评分，评分最高者为起火房间；
5. **蔓延时序计算**：以房间为节点、连通关系为边构建房间图，从起火房间出发按烧毁评分与连通性计算每个房间的起火时刻与强度曲线，生成全局时序表；
6. **Blender 自动化**（独立子进程）：导入 OBJ → 场景预处理 → 按时序表生成火焰粒子、烟雾体积、焦痕贴图动画、火光 → 按真实采集点位设定摄像机轨迹 → 逐帧渲染；
7. **转码与交付**：FFmpeg 合成 1080P 母版并转码 720P；前端展示进度，完成后在线预览与下载。

## 4. 详细功能需求

### 4.1 用户端（Front-end，单页应用）

#### F1 场景导入模块

- 输入框接收 **sceneCode**；
- 提交后调用 `/scene/getSceneList` 校验场景存在，并展示：场景名称、相机类型（mega/kankan）、点位数量、创建时间；
- 场景不存在时给出明确错误提示（场景码无效 / 无权限 / 接口异常）。

#### F2 参数设置与起火点确认模块

- **自动识别结果展示**：以房间列表形式展示各房间烧毁评分（如 0~100 分）与识别出的起火房间；同时展示每个点位的全景图缩略图（点击可查看大图）；
- **手动修正**：识别置信度低或用户不认同时，可从房间下拉列表手动指定起火房间；
- **时间参数**：视频时长（默认 60 秒，可选 30/60/120 秒）、蔓延速度倍率（0.5x ~ 2x，影响全局时序拉伸）；
- **输出参数**：分辨率档位（1080P / 720P）。

#### F3 任务进度模块

- V1 为单任务串行，同一时间仅一个任务运行，新任务在确认后排队等待；
- 任务状态机：`排队中 → 鉴权/下载中 → 烧毁识别中 → 时序计算中 → Blender 渲染中（显示帧进度 xx/xxx）→ 转码中 → 已完成 | 失败`；
- 失败时展示失败阶段与错误摘要，提供"查看日志"（本地日志文件）与"重试"按钮；
- 历史任务列表（保留最近 N=10 个，含任务参数、耗时、状态），支持删除（连带清理本地数据）。

#### F4 视频预览与导出模块

- 完成后网页端 `<video>` 直接播放；
- 提供 MP4 下载按钮（1080P 母版 / 720P 轻量版，实际渲染 1080P 一次 + FFmpeg 转码，**不重复渲染**）；
- 可选叠加信息（渲染时烧录）：时间码、房间名称标签、蔓延进度条。

### 4.2 核心处理端（Back-end & Engine）

#### F5 4DKankan 数据桥接层

**鉴权**：

- 支持两种方式：接入信息中的 appkey（Authorization 头直接调用），或 `/user/v1/login`（用户名+密码明文，**仅在本机配置文件中加密存储，绝不进入前端与日志**）；
- 凭据保存于本机配置目录（如 `config/credentials.yaml`，V1 用本机文件权限保护即可）；
- 首次使用提供"接入信息配置页"引导用户填写。

**接口封装**（全部 9 个接口，V1 实际用到的标注 ★）：

| 接口 | 用途 | V1 使用 |
|---|---|---|
| POST `/scene/getSceneList` | 场景校验与信息展示 | ★ |
| POST `/scene/getSceneObj` | 下载 OBJ 模型（返回 string[] 下载链接，可能按房间分段为多个文件） | ★ |
| POST `/scene/getScenePanorama` | 下载全景图（烧毁识别输入） | ★ |
| POST `/scene/getScenePointInfo` | 采集点位位姿（四元数+位移）与所属房间（room 字段），用于运镜与房间归属 | ★ |
| POST `/scene/getSceneRaw` | 点云与深度图（V1 预留：可用于 V2 代理几何/遮挡体生成） | 预留 |
| POST `/scene/getSceneViewUserFile` | 场景编辑数据压缩包 | 预留 |
| POST `/scene/getSceneVideo` | 球幕视频（限流 60 秒/次，需重试策略） | 预留 |
| POST `/scene/sceneMarkShape/saveOrEdit` | 标注数据写回（V2：用户修正的起火点回写场景） | 预留 |
| POST `/user/v1/login` | 获取 token | ★（按需） |

**关键设计点**：

1. **临时 URL 即时转存**：所有下载链接视为短时有效，调用后立即下载到本地数据目录，失败自动重试 3 次（指数退避）；
2. **数据目录规范**：`data/<sceneCode>/{obj/, panoramas/, points.json, raw/, result/}`；
3. **坐标系对齐验证**（开发期任务）：OBJ 网格坐标系与点位 pose 坐标系的一致性需在 M1 用真实场景验证；不一致时在桥接层做统一变换并记录变换矩阵。

#### F6 起火点自动识别模块

**输入**：各点位全景图（`getScenePanorama`）+ 点位信息（room 字段）。

**算法思路（V1 启发式）**：

1. 对每张全景图做颜色分析，统计"烧黑像素"占比——低亮度 + 低饱和度（黑/深褐）像素，按阈值划分，同时检测煤烟覆盖特征；
2. 排除干扰：阴影区、深色装修、曝光不足区域（可结合全景图拍摄参数与多图对比抑制误判）；
3. 按 room 字段聚合，得到**房间级烧毁评分**（0~100）与每张图的评分明细；
4. 评分最高房间 = 起火点；输出各房间评分排序 + 置信度（评分差是否显著）。

**兜底**：置信度低（如最高分与次高分差 < 阈值）时，前端提示用户手动选择起火房间。

**验收口径**：识别结果应与"现场勘察判定的起火部位"一致率 ≥ 80%（以人工复核为准，V1 仅要求可用，不做硬指标承诺）。

#### F7 程序化蔓延时序引擎

**输入**：房间图 + 各房间烧毁评分 + 起火房间 + 视频时长 + 速度倍率。

**房间图构建（V1）**：

- 节点 = 房间（来自 point info 的 room 字段与 OBJ 分段）；
- 边 = 房间连通关系。V1 方案：从点位可视性（visibles 字段：某点位可见哪些其他点位）推导跨房间可视 → 视为连通；无法推导时按"同层全连通 + 用户手动增删边"兜底。V2 可升级为几何门洞检测。

**蔓延模型（V1）**：

- 从起火房间出发，蔓延概率/速度正比于：邻接关系、目标房间烧毁评分（烧得越重 → 越早、越猛烈地参与燃烧）、房间面积；
- 每个房间生成一条强度-时间曲线，阶段划分为：`未起火 → 增长期 → 全盛期 → 衰减期 → 熄灭`；
- 全局输出：`timeline.json`（房间 × 时间轴的强度曲线采样表），并支持倍率拉伸。

**验收口径**：蔓延顺序应与勘察报告描述的"蔓延路径"大体一致；不一致时可通过手动调整房间边/倍率修正。

#### F8 Blender 自动化脚本引擎（独立子进程）

> **架构约束**：bpy 绑定 Blender 自带 Python（Blender 4.2 LTS = Python 3.11），后端**不 import bpy**；通过 `blender -b -P script.py -- json参数文件` 子进程方式调用，参数与进度均通过 JSON 文件/标准输出交互。

**场景预处理**：

- 导入各房间 OBJ（含纹理），统一缩放与坐标变换（采用 F5 验证后的变换矩阵）；
- 应用变换、合并材质，清理游离面片；
- 程序化路线**无需**水密化/封堵网格（不跑流体模拟），仅需各房间包围盒用于烟雾体积与粒子的空间约束。

**火焰表现（按 timeline.json 驱动）**：

- 每房间一套火焰粒子系统：公告板火焰贴图（billboard sprites）+ 发光材质，粒子数量/亮度/高度由该房间当前强度值驱动；
- 烟雾：每房间噪波体积（程序化扰动，非物理模拟），密度随强度曲线变化；
- 焦痕：房间墙面/地面贴图随时间加深的 shader 动画（烧毁评分越高的房间最终越黑）；
- 火光：每房间 1~2 盏带随机闪烁的点光源，颜色随温度阶段由橙红转暗红；
- 可选烧录：时间码、房间标签、蔓延进度条。

**摄像机运镜**：

- 主方案：使用 `getScenePointInfo` 的真实采集点位（rotation 四元数 + translation），**按采集顺序**生成关键帧轨迹，插值生成平滑运镜；
- 兜底：点位数据缺失时采用环绕/固定视角（V1 固定预设，不做自动路径规划）；
- 每帧相机视野需在房间包围盒内（防穿墙），出界时自动修正。

**渲染与输出**：

- V1 渲染引擎：**Eevee**（公告板火焰 + 体积烟雾在 Eevee 下质量可接受，速度远快于 Cycles，单机 CPU 亦可渲染）；
- 输出 PNG 帧序列（防中断可续渲）→ FFmpeg 合成为 1080P H.264 MP4 → 转码 720P；
- 分辨率：24fps；1080P（1920×1080）母版 + 720P（1280×720）派生；
- 进度上报：每渲染 1 帧写入进度文件，后端读取并推给前端。

**性能预算（V1 目标）**：

| 参数 | 值 |
|---|---|
| 60 秒视频 @ 24fps | 1440 帧 |
| Eevee 渲染速度（本机独立显卡） | 约 1~3 秒/帧 |
| 单任务总耗时（含识别/转码） | **目标 ≤ 1.5 小时**（无独显 CPU 渲染时放宽至 ≤ 4 小时） |

#### F9 视频后处理

- FFmpeg：帧序列 → 1080P MP4（H.264, CRF 20）→ 720P MP4；
- 可选：加片头信息（场景名称、参数说明）；
- 输出至 `data/<sceneCode>/result/`。

## 5. 火灾演变视频内容定义（新增）

成片必须包含以下视觉要素，缺一不可：

| 要素 | 表现方式 | 说明 |
|---|---|---|
| 火焰 | 公告板粒子 + 发光 | 起火房间最先出现，随蔓延逐房间出现；强度随曲线增长/衰减 |
| 烟雾 | 噪波体积 | 起火房间烟雾最早最浓，蔓延后各房间依次起烟 |
| 焦痕 | 贴图加深动画 | 烧过区域的墙面/地面逐渐变黑，最终状态应与**灾后实拍贴图一致**（这是"以终为始"的校验点：动画终点 = 真实烧毁程度） |
| 火光 | 闪烁点光源 | 照亮周边，随强度变化 |
| 信息层（可选） | 时间码/房间标签/蔓延进度条 | 烧录进视频，便于汇报讲解 |

## 6. 技术架构（单机版）

```
浏览器 (localhost) ── HTTP ──> FastAPI 后端 ──> 任务状态机（内存/JSON 持久化）
                                     │
                     ┌───────────────┼────────────────┐
                     ▼               ▼                ▼
              4DKankan 接口     Blender 子进程      FFmpeg 转码
             （数据桥接层）      （bpy 脚本+JSON）   （母版+720P）
```

| 层 | 技术选型 | 说明 |
|---|---|---|
| 前端 | Vue 3 + Vite + 原生 CSS（或 Element Plus） | 单页应用，本机 5173 端口，开发期与后端同机 |
| 后端 | FastAPI + uvicorn | 本机 8000 端口；**V1 不使用 Celery/Redis**（Windows 兼容性差），采用单任务串行状态机，任务状态持久化为本地 JSON 文件，重启可恢复 |
| 渲染引擎 | Blender 4.2 LTS（bpy） | 独立子进程调用，与本后端解耦 |
| 视频处理 | FFmpeg | 帧合成与转码 |
| 图像分析 | OpenCV / numpy | 全景图烧黑像素分析 |
| 存储 | 本地文件系统 | 数据目录按 sceneCode 组织；任务完成后 N 天（默认 30 天，可配置）自动清理 |
| AI 辅助 | Claude Code + DeepSeek | Claude Code 统筹脚手架与后端；DeepSeek 辅助 bpy 粒子/体积节点与全景图分析算法攻坚 |

**依赖要求**：Blender ≥ 4.2 LTS、FFmpeg、Python 3.11+、Node.js 20+。运行环境为 Windows 11（单机），后续 V2 可迁移至 Linux 服务器（Docker 化）。

## 7. 非功能需求

### 7.1 性能

- 单任务全流程目标 ≤ 1.5 小时（有独立显卡），无独显时 ≤ 4 小时；
- 前端进度刷新频率 ≥ 1 次/2 秒，渲染阶段显示帧进度。

### 7.2 失败处理

- 各阶段失败可重试（下载重试 3 次；渲染支持从已完成帧续渲）；
- 所有失败保留现场（已下载数据、日志、已渲染帧），提供日志查看入口；
- 任务失败不影响历史任务结果。

### 7.3 数据合规与安全

- 火灾现场数据仅存本机，**任何数据不得上传至外部服务**（这是单机版的产品承诺）；
- 凭据本机加密存储，日志中脱敏（不打印 token/密码）；
- 任务数据按配置自动清理（默认保留 30 天）；
- 视频中可烧录"演示用途"水印（默认开启，可关闭）。

### 7.4 兼容性

- 支持 Windows 11（V1 目标平台）；浏览器 Chrome/Edge 最新版。

## 8. 里程碑规划

| 里程碑 | 内容 | 产出与验证 |
|---|---|---|
| **M1 数据桥接** | 鉴权封装、9 接口封装、临时 URL 转存、**坐标系对齐验证** | CLI 工具：输入 sceneCode 可拉取全部数据到本地目录；用真实场景验证 OBJ 与点位坐标系一致 |
| **M2 Blender 管线** | OBJ 导入预处理、点位运镜、静态渲染 | 无火场景 flythrough 视频（1080P，Eevee），运镜不穿墙 |
| **M3 识别+时序引擎** | 烧黑识别、房间图构建、蔓延时序计算 | 输出各房间烧毁评分与 timeline.json；与勘察结论人工比对 |
| **M4 火焰表现整合** | 火焰/烟雾/焦痕/火光动画 + 全流程打通 | 第一条完整的火灾演变视频（含时间码），焦痕终点与实拍一致 |
| **M5 Web 应用** | 前端参数页、任务进度、预览下载、失败处理、数据清理 | 可交付单机版：输入 sceneCode → 出片全流程无人工干预 |

每个里程碑通过后方进入下一个；M1 为最大不确定性所在（接口真实行为验证）。

## 9. 验收标准（V1 交付）

1. 输入有效 sceneCode，全流程无人值守完成，产出 1080P + 720P MP4；
2. 视频要素齐全（火焰/烟雾/焦痕/火光/时间码），焦痕终点与灾后实拍一致；
3. 自动识别的起火房间与勘察判定一致率 ≥ 80%（人工复核统计）；
4. 蔓延顺序与勘察报告描述大体一致，偏差可通过参数调整修正；
5. 任务失败可重试，历史任务可回放下载；
6. 无任何数据离开本机。
