# 产品需求：房间火灾演示系统

文档修订：2026-11-13，工程整理版 4。当前有效需求；开发进度见 [PROJECT_STATUS](PROJECT_STATUS.md)，技术实现见 [ARCHITECTURE](ARCHITECTURE.md)。本文修订号、V6–V9里程碑和Room8 V1演示版是三个不同概念。

## 1. 目标与用户

面向研究人员、老师和演示人员，将室内扫描资产组织为可选择的房间，生成并查看单房间火灾蔓延演示视频。输入包括 OBJ、材质贴图、全景图、相机点位及经核验的户型；输出包括独立房间资产、时序、MP4 和可追溯的运行报告。

这是程序化视觉演示，不是 CFD 火灾动力学仿真，不用于证明真实起火原因或精确火势过程。灾后扫描无法唯一恢复灾前房间；现有视频不代表灾前重建已完成。

| 能力 | 已达到的范围 | 尚未达到的范围 |

| 数据管理 | PostgreSQL 本场景真实导入版本1，6房间/22点；指定Room8交付6份已上传登记，幂等/关系/签名Range核对通过 | 其他场景及全量运行附件未验证；网页播放未重新验收 |

Room8 V1 为有已知限制的阶段性演示基线，暂不重新渲染。使用平层工程近似 `floor_z=-1.35m`；不得自动将该值用于其他房间。基线版本和验收证据见 [RELEASES](RELEASES.md)。

## 3. 下一阶段最小用户流程（待实现）

1. 进入房间列表，选择已核验的 Room8，看到点位数量、资产版本和已有视频。
2. 查看房间预览与 R3 预设说明；模型预览先用检查图，交互式 GLB 为可选增强。
3. 选择受控渲染档位和默认 overview，明确确认后提交新版房间任务。
4. 查看任务阶段、完成帧数、错误信息和实际耗时，失败可追溯。
5. 技术完成后播放、拖动、下载对应任务的 MP4；人工审核状态独立展示。

公共操作日志、服务器最小验收、工程基线进入main、本场景真实导入及Room8指定交付登记已完成。Room8任务API本地已实现，待远端验收后建设网页。后端通过可信适配层组织房间/资产；创建依赖数据库中的已核验登记，已有任务查询与本地视频播放以文件为准，不依赖数据库在线。现有 `/api/catalog` 是数据库查询接口；网页不得调用旧全场景渲染接口代替房间任务。

对象登记、Room8任务API和最小网页统一使用feat/room8-web-registration-api分支。首批登记CLI已远端验收；第二批API已本地实现，服务端提交开关默认关闭，要求显式确认和幂等键、复用安全启动器及独立输出。正式档须有效审核或服务端显式策略，客户端不能绕过。网页及API远端部署待完成，完整契约见[Backend](../backend/README.md#room8新版任务api本地实现远端待验收)。

## 4. MVP 范围与验收

| 需求 | 必要行为 | 验收证据 |
| --- | --- | --- |
| 房间选择 | 仅开放已核验、具备可用资产的 Room8 | 列表、预览及资产版本一致；无效房间不进入渲染 |
| 参数控制 | R3 艺术配置冻结；质量档、机位由后端允许列表控制 | 不允许提交任意脚本路径、任意配置 JSON 或改写基线 |
| 新版任务入口 | 后端调用普通 Python 启动器，再启动 Blender 子进程 | 无业务代码 import bpy；单独任务号；冲突请求明确拒绝 |
| 进度与历史 | 按任务读取状态、manifest、日志摘要 | 刷新不丢任务；失败不冒充完成；不覆盖旧任务 |
| 视频交付 | 只交付该任务通过技术验证的文件 | 帧数/分辨率/FPS/时长正确，完整解码通过，浏览器播放与 Range 拖动可用 |
| 关联与追溯 | 场景、房间、资产版本、任务号统一 | 按 [数据规范](DATA_ASSET_SPEC.md) 追溯配置、源码指纹和产物 SHA256 |
| 服务隔离 | 数据库失败不拖垮既有 CLI 渲染与 Legacy 功能 | 相关接口返回可诊断错误，文件任务仍可查询 |
| 操作追踪 | 用户动作、每次API、CLI及后台关键阶段有时间、结果、耗时及关联ID | 可从按钮/请求追到任务和失败阶段；先实现公共组件，前端上线后验收真实闭环，详见[日志契约](OBSERVABILITY.md) |

新任务技术完成不等于人工视觉验收通过。沿用 `awaiting_visual_review` 的含义，不把它静默改成“审核通过”。正式档 1280×720/24fps、测试档 960×540/12fps 为现有引擎能力；网页尚未开放这些选择。

## 5. 工程与数据要求

- 原始全屋资产、人工核验、基础房间及历史视频不可覆盖；展示剖面和火灾任务分别保存派生版本。
- Git 保存源码、测试、公共配置和脱敏发布信息；真实模型、户型、视频、私有报告和凭证不入库。
- 运行状态 JSON 是当前任务状态依据；PostgreSQL 管理关系和查询摘要，MinIO 管理已登记的文件对象。职责与实际接入情况须分开表述。
- 性能记录准备、逐帧、编码、验证及总时间。约 20 分钟是优化目标；Room8 的约 6 分钟实测不构成所有房间的承诺。
- 正式运行功能变更须新增对应tests测试，标注需求、架构、环境与未验证项；API/CLI/前端/后台新增操作须考虑结构化日志和脱敏测试。远端GPU、视频和视觉验收不能由离线替身替代。
- 当前交付为本地文件、局域网或 SSH 隧道。预签名只能解决权限，不能让私网地址自动公网可达。

| 5 最小网页与对象登记 | Room8/R3任务、进度、播放及MinIO新版登记 | 调用新引擎，操作可追踪，上传核对后登记 |
| 后续增强 | 生命周期、Hybrid、自动高度、完整产品化 | 单独任务和验收，不混入当前基线 |

自动高度目前仅做设计：分别输出地板候选、顶面候选和净高，结合占比、第二候选差距及空间覆盖判置信度；低可信时返回异常，不把众数等同于物理地板。设计见架构文档，不改现有裁切算法。

V6–V9 保留为历史里程碑标签，按当前优先级执行：V6 出片已有两条不同链路；V6.1 东莞公网展示仍待部署条件确认；V7 部分单房间/GPU/续跑已提前实现，观测网页未完成；V8 跨房间/智能运镜及 V9 完整产品化继续后排。最小网页从原 V9 范围前置，不宣称整个 V9 完成。

东莞方案保留：楼下 GPU 渲染，主动上传经允许外发的成片，东莞复用实验室网站入口提供 HTTPS 播放，无需为播放加显卡。入口、认证、存储、权限与带宽尚待确认；本轮不部署。

原路线与实验过程原样保存在 [历史 PRD](archive/20261107_pre_baseline/PRD_V1.1.md)。历史短片前置、旧 GPU 中间配置和旧冷启动步骤不作为本轮执行指令。
